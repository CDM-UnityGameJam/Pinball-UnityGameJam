# Luck Number v0.4：命中充能补牌

## 已实现

- 倒计时改为充能：基础100，每次出牌增加50需求；从满手出一张需150，连续三张累计250／350／450时补回。
- 已有进度不因出牌清空；补回一张后若仍缺牌，下一张需求100；溢出进入下一张，满手清零。
- 缺牌且正常游玩时自然恢复10/秒；有效物理命中+2，命中开始时持有任意同号牌则+3。多张、类型和短路均不改变同号奖励。
- 单怪独立1秒充能冷却，不改变原有碰撞伤害与附魔命中冷却。致死碰撞计入；技能、燃烧和击杀不回能。
- 所有来源、所有球共用滚动1秒16点限额。超额立即舍弃；出牌和补牌不重置限额历史。
- 先锁定命中开始时手牌，完成原有伤害和附魔后结算充能与补牌，新牌从下一次碰撞生效。
- 暂停、等待发球及结束时停止充能；掉命保留进度与需求；重开创建全新账户。
- 保留号码限定被动、无号码限制的主动技能、当前概率／幸运／强度／刷怪配置。未增加随时间加快刷怪。

UI 保持英文：`Recharge: 74 / 150`、`Next cast: required charge +50`、`+2` / `+3 MATCH`。限额裁切时只显示实际获益，零获益不弹字。

## 配置

GameManager > Luck > Recharge：基础需求、出牌追加需求、自然速度、命中奖励、同号奖励、单怪冷却、滚动总上限。

记录缺牌有效时长、缺牌期间物理命中频率、可提供充能的命中频率、同号比例、实际充能速度、补牌间隔和平均怪物数。结束／重开 Console 与开发工具统计包含这些指标。低装备仍为用户确认的0～1张。

## 本次已执行的验证

- 独立C#充能核心测试通过：30,000次随机事件的滚动窗口独立求和比对，窗口内不超过16；跨整秒边界不重置；满手／出牌不重置限额；溢出和250／350／450累计需求。
- 稳定节奏模型通过：无命中一张15秒、三张25／35／45秒；每秒一次、交替异号／同号时，一张12秒、三张20／28／36秒。这些是规则模型，不是实际弹球测量。
- 使用当前Unity 6000.6.8f1自带Roslyn和项目现有引用，运行程序集与Editor程序集编译均通过；仍有原有弃用API警告。

## 未完成的验证及原因

Unity编辑器批处理启动失败：授权客户端校验失败，握手返回ApiErrorResponse。因此本次未运行Unity集成验收、界面截图及真实弹球密度测试，不能声称高密度稍难或常规节奏已校准。

已准备以下入口，Unity授权恢复后可运行：

- `LuckyPinball > Luck Number > Check Recharge Account`：独立账户检查。
- `Run Acceptance Checks (Play Mode)`：含充能集成、命中／致死／多球冷却、短路与空手、同号快照、新牌下次碰撞生效、暂停和溢出等检查，以及之前的战斗回归。
- `Compare Recharge Density (Real Physics, Play Mode)`：重开当前游玩，使用实际球桌、球体物理、相同自动挡板控制器，常规与2倍固定刷怪尝试频率各3个种子，最长120有效秒。无合成命中，不随时间加快刷怪。输出 `Data/v04-real-physics.csv` 和 `Docs/LuckNumberV04Physics.md`。
- `Stop Physical Recharge Measurement`：提前结束该测量。

真实物理自动操作也不等同人工试玩；不根据脚本化固定命中模拟自动调参。当前仍保留2／+1／10／16的默认配置。常规平均等待应落在旧版±10%内；高密度是否略难需比较实际命中、越线、落球和技能影响，不能由限额单独认定。

批处理可用 `-executeMethod RechargeBatchCheck.Run` 跑功能验收，`RechargeBatchCheck.RunDensity` 跑物理密度测量。独立核心也可用Windows C#编译器编译 `Assets/Scripts/RechargeAccount.cs`、`Assets/Scripts/Editor/RechargeAccountChecks.cs`、`Tests/RechargeAccountRunner.cs` 后直接运行，无需Unity授权。
