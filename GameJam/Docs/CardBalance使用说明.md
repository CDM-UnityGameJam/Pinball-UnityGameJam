# 卡牌数值配置与快速调试：中文使用说明

适用场景：`Assets/Scenes/Pinball.unity`。游戏界面保持英文。

## 1. 配置入口

默认资产：`Assets/Settings/DefaultCardBalance.asset`。

在场景中选中 GameManager，通过 **Card Balance Config** 引用指定资产。双击引用或在 Project 中选中资产，即可编辑。

默认资产从当前 Pinball 场景迁移：24 项原有标量参数、三张持牌数量表、三个元素各四行档位参数。原场景内嵌的 LuckTuning 已移除，LuckTuning 作为配置数据与共用计算逻辑继续使用。

复制配置资产可制作不同平衡版本；在编辑模式为 GameManager 指定所需资产，再开新局测试。

## 2. Inspector 分组

| 分组 | 可调整内容 |
|---|---|
| Recharge & charge | 基础补牌需求、每张追加需求、自然恢复、事件充能、滚动预算和最低充能 |
| Ball collision damage | 普通碰撞伤害 |
| Held Arc | 电击伤害、范围、持有 1～5 张时的额外目标数 |
| Held Spark | 燃烧 DPS、持续时间、附近范围、持有 1～5 张时的附近目标数 |
| Held Shockwave | 眩晕时间、免疫时间、持有 1～5 张时的作用半径 |
| Shared flame timing | 主动火与被动火共用的跳伤间隔 |
| Active Arc / Spark / Shockwave | 各元素独立的四档目标模式、数量及波数／持续时间／首波眩晕 |
| Same-element stacking | 每多一张同元素牌增加的雷波数、火焰时间；震波固定一次冲击 |
| Dice presentation & reveal | 揭骰延迟；骰子仍为公平六面骰 |
| Existing enemy queue spacing | 从原配置保留的怪物排队安全间距 |


雷的额外目标不包括直接撞到的怪物。火的直接目标单独点燃，不占附近目标名额。持牌震波只有眩晕，没有额外伤害。元素免疫规则保持不变。

## 3. 主动技能四档

- **Base**：没有骰子匹配牌号，仍施放基础技能。
- **Hit**：单张出牌，骰子匹配。
- **Full Field**：多张同号牌，恰好一颗骰子匹配。
- **Jackpot**：至少两颗骰子匹配。

每个元素、每个档位的 **Target Mode** 独立设置：

- **Limited**：限制数量，显示 Target Count。
- **All Eligible**：覆盖提交时的全场合格目标。

例如，只修改 Active Spark 的 Base 目标数为 2，不会影响 Base 雷或震波。

重复元素在四档中都叠加：额外张数为该元素本批张数减 1。雷增加波数，火增加时间；震波始终只有一次冲击，眩晕时长按档位配置，不随同元素张数增加。

## 4. 计算预览

Inspector 底部的 **Actual calculation preview** 可选择：

1. Element：元素。
2. Held cards of this element：持有数量，1～5。
3. Cast cards of this element：本批该元素出牌数量，1～5。
4. Tier：开奖档位。

预览显示持牌效果、主动范围、最终波数或燃烧时间、总效果时间、单目标理论总伤害、追加补牌需求。

雷和震波还显示首波到末波的时间跨度。震波的总效果时间取波次跨度与首波眩晕时间中较大者。

火焰使用实战同一取整方法：

`每跳伤害 = floor(DPS × 跳伤间隔 + 0.5)`

因此，小正数 DPS 可能每跳实际为 0；预览会显示 0，不会用未经取整的理论值误导。

理论火焰跳数按新施加且没有其他燃烧重叠的状态计算。所有理论伤害均假设目标持续存活、可受该元素影响。预览补牌成本假设本批仅包含所选元素。

充能公式也在 Inspector 中显示，可输入上一秒已经获得的战斗能量：

`实际战斗充能 = min(单次能量, max(最低充能, 常规预算 − 上一秒战斗能量))`

自然恢复不占战斗预算。最低收益可使滚动一秒的总战斗收益超过常规预算，这属于预期规则。

## 5. 运行中修改何时生效

| 内容 | 生效方式 |
|---|---|
| 持牌参数 | 下一次符合条件的碰撞使用新值 |
| 主动技能参数、目标范围、叠加收益、揭骰延迟 | 提交时固定；已经提交的批次及后续波次保留旧值 |
| 已有燃烧 | 保留其 DPS、跳伤间隔与结束时间；主动与被动来源分别保存 |
| 新燃烧或成功刷新 | 使用该次施加的参数；已提交主动技能传入的是其提交时快照 |
| 已有眩晕与免疫 | 保留已经计算的结束时间 |
| 自然恢复与新充能事件 | 立即使用新值 |
| 当前补牌进度与当前需求 | 保留；新增出牌成本及下一张补牌的基础需求使用新值 |

燃烧刷新沿用原规则：不会重置已经排定的下一跳；较短施加不会缩短同来源原有的结束时间。主动火不会被被动火续时，同一时刻按仍有效来源中较高的 DPS 结算。

修改配置不会重建手牌、清空能量。

**Inspector 修改配置资产是正式修改，退出 Play Mode 后仍会保留。** F8 操作只改变当前运行状态。

## 6. F8 Cards 页

进入 Game 视图，按 **F8**，切换到 **Cards**。该功能仅在编辑器和 Development Build 中启用。

显示：当前配置名称、手牌及各元素数量、补牌进度与需求、强化库存，以及最近一批的牌、骰面、档位和已固定的技能参数。

| 控件 | 用法 |
|---|---|
| Card number / 元素按钮 | 指定新卡数字和元素 |
| Add specified card to empty slot | 向空位补入指定卡，满手时拒绝，不替换现有牌 |
| Next dice | 填写骰面，如 `4, 6`；也接受空格或分号分隔 |
| Fix next batch dice (one use) | 固定下一批骰子，使用一次后恢复随机 |
| Restore random dice | 主动清除固定骰面 |
| Fill current recharge through normal refill | 填满当前补牌进度，并走正常补牌入口；需要正常战斗且缺牌 |

固定骰面数量必须等于提交张数。例如设置 `4, 6` 后，只能提交两张同号牌。数量不符会拒绝整批，保留手牌、固定骰面和补牌账目。

新开一局会恢复初始手牌，清空固定骰面、强化和充能等运行状态。

### 示例：测试两张火 4 的三种结果

先出牌腾出空位，再用 Cards 页补入两张 4 号 Spark，选择它们合出。

| 固定骰面 | 默认结果 |
|---|---|
| `2, 6` | Base：1 只合格目标，燃烧 3 秒 |
| `4, 6` | Full Field：全场合格目标，燃烧 8 秒 |
| `4, 4` | Jackpot：全场合格目标，燃烧 10 秒 |

每次成功提交两张牌，默认增加 100 点补牌需求，并获得两次强化。

## 7. 配置错误与验证

Inspector 会指出错误字段或行，例如负值、非有限数、零跳伤间隔、零波次、缺失数量表、最低充能超过单次能量。配置缺失或无效时使用安全默认值，并显示／记录提示；不会改写有问题的资产。

验证菜单：

- `LuckyPinball → Card Balance → Check Rules`
- `LuckyPinball → Card Balance → Run Integration Checks (Play Mode)`

当前验证结果见 `Docs/CardBalance验证记录.md`。Play Mode 集成验收仍受 Unity 授权客户端校验失败阻塞，Inspector 和 F8 页实际布局也尚未完成编辑器内确认。
